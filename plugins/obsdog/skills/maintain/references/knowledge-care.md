# Knowledge care during work

Use these criteria when deciding how to incorporate findings into existing
knowledge. Read the explanation and sources, write the current understanding,
and check the result: Observe → Diagnose → Improve → Observe.

## Explain the subject and its source

Keep the direct answer with the background, prerequisites, version and environment
needed to apply it. Record source locations and what was checked. Distinguish
specification intent, a code version's implementation and runtime observations.

Use ObsDog for explanations, decisions, reasons, investigations and work context.
Link to the source that maintains the contract or procedure. When the task also
includes changing that source, make the corresponding source update and record
its result. Keep source changes and knowledge changes distinguishable.

Record observations and hypotheses with their status and next check while the
investigation proceeds. When sources disagree, retain their scopes and explain
the difference being investigated. Update the explanation as checks resolve it.

## Keep readable units and a clear home

Update the existing note for the subject. Combine overlapping explanations when
they describe the same subject and scope. Keep different versions or environments
clear when they need distinct answers. Split independently changing subjects
using a supported structural operation.

Keep conditions, warnings and prerequisites with the procedure they qualify.
Preserve the decision history needed to explain the present answer. Link replaced
guidance to its current explanation and preserve revision history.

Read both ends of a relationship. State the question the destination answers and
use its actual note or source location. Connect overviews, procedures, decisions
and detailed explanations. Follow [retrieval authoring](retrieval-authoring.md)
when adding lookup vocabulary or repairing navigation.

## Make and check the change

Use the task's selected Space and source/upload scope. Read the current document
and block revisions, then apply a supported update with its reason and sources.
Use [care execution](care-execution.md) for merge, split, move, supersede and
recovery operations.

Read back the accepted revision. Check the explanation, applicability, structure
and links. For a new note or search repair, check the original task question.
Return saved locations and any unfinished operation or check.

On a revision conflict, read the current content and reconcile the intended
change. After an unknown write outcome, resolve the original request before
retrying. Preserve another writer's changes. A supported ordinary update can
proceed independently of an unavailable structural operation.

## Record checks with the selected runtime

Use [remote MCP](../../find/references/remote-mcp.md) for connected tools or
[CLI usage](cli.md) for an explicitly selected local library. Their references
supply exact operations, request identity, source records and supported labels.

Record what was read, checked, changed and used. Keep agent review attributable
and tie it to the inspected source and revision. When the task uses a note,
record that actual use and supported feedback through the runtime. A saved
revision verifies the content of the update; later task use supplies evidence
of how the explanation helped.
